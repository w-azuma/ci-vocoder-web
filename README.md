# きこえ方の体験 ─ ノイズボコーダ（ブラウザ版）

スライダーでチャネル数を動かしながら、音楽が「スペクトル情報が少ない状態」でどう聞こえるかを
**リアルタイムで**聞き比べられる Web アプリです（TypeScript + Vite + Web Audio API）。

> **注意：これは人工内耳を使う人の実際の聞こえ方そのものではありません。** 正常聴力者に向けた近似です。

## 動かし方

```bash
npm install
npm run dev        # 開発サーバー → 表示された http://localhost:5173 を開く
npm run build      # 型チェック + 本番ビルド（dist/ に出力）
npm run preview    # ビルド結果の確認
```

`package.json` のあるこのフォルダで実行してください。

## できること

- **チャネル数 1〜22** をスライダーかプリセット（2 / 4 / 8 / 12 / 16 / 22）で切り替え。再生したまま、その場で変わります。
- **原音との A/B 切り替え**
- **自分の音声ファイル**の読み込み（wav / mp3 / m4a など）。ファイルはブラウザ内で処理され、外部には送信しません。
- **スペクトログラム**表示と、チャネル境界のガイド線
- 詳細設定：キャリア（雑音 / 正弦波）、包絡線の遮断周波数（10〜400 Hz）
- キーボード操作：`Space` 再生/停止、`A` 原音と切り替え、`←` `→` チャネル数

## しくみ

`src/vocoder.ts` で、チャネルごとに Web Audio のノードを次のようにつないでいます。

```
入力 → 帯域通過×2 → 全波整流(WaveShaper) → 低域通過×2 ＝ 包絡線
                                                       ↓（GainNode の gain を動かす＝変調）
帯域雑音（白色雑音 → 帯域通過×2） ─────────────→ GainNode → 帯域通過 → 出力
```

- 帯域の境界は Greenwood 関数で決めています（`src/greenwood.ts`）。蝸牛上でほぼ等間隔になります。
- チャネル数を変えるとノードを作り直し、40 ms のクロスフェードでつなぎます。
- 出力の大きさが原音と同じになるよう、自動で音量を合わせています（`src/engine.ts` の `tick()`）。そのため、チャネル数を変えても音量差で聞こえ方が変わったように感じることはありません。最後にリミッターも入れて、過大音量を防いでいます。

Python 版（`vocoder.py`）と同じ考え方ですが、Python 版はファイルをまとめて処理し、こちらはリアルタイムで処理します。
フィルタの次数などは少し異なります。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `src/vocoder.ts` | ボコーダ本体（ノードの組み立て） |
| `src/greenwood.ts` | 周波数帯の境界の計算 |
| `src/engine.ts` | 再生・A/B 切り替え・自動音量調整・リミッター |
| `src/spectrogram.ts` | スペクトログラム表示 |
| `src/demo.ts` | デモ曲（きらきら星、パブリックドメイン）をブラウザ内で合成 |
| `src/main.ts` | 画面の操作 |

## 公開（GitHub Pages）

`vite.config.ts` で `base: "./"` にしているので、`npm run build` でできた `dist/` の中身をそのまま置けば動きます。

## 限界

- 正常聴力者に向けた近似であり、人工内耳を使う人の実際の聞こえ方そのものではありません。
- 次の要素は再現していません。
  - 電流の広がり・チャネル間の干渉
  - 電極の挿入位置による周波数のずれ
  - 埋め込み期間や聴力喪失の原因などの個人差
  - 機器ごとの処理の違い
- 公開デモや動画では、市販曲ではなく、パブリックドメインの曲、CC ライセンスの曲、自作曲を使ってください。
